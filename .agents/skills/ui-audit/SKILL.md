# UI Audit — системный аудит интерфейса

Проектный скилл для поэтапной ревизии экранов и компонентов `open-hackathon`. Помогает находить визуальный шум, рассинхрон компонентов и пропущенные состояния без изменения бизнес-логики.

## Когда применять

- Перед редизайном или полировкой существующего маршрута.
- При аудите всего приложения по списку страниц и компонентов.
- Перед сдачей новой страницы или крупного UI-блока как финальная самопроверка.

## Чек-лист проверки

### 1. Визуальная иерархия
- [ ] На странице чётко различимы 3 уровня: заголовок страницы (`<h1>`), главное действие (Primary CTA), второстепенные действия и вспомогательные ссылки.
- [ ] Внутри каждой карточки/секции понятен порядок чтения: метаданные/статус → заголовок → краткое описание/параметры → действие.
- [ ] На одном экране или в одной карточке не более одного главного акцентного действия (`variant="default"`); деструктивные действия отделены от обычных.

### 2. Консистентность отступов, размеров, радиусов и теней
- [ ] Повторяющиеся примитивы (кнопки, инпуты, `select`, `textarea`, карточки, бейджи, алерты) выглядят одинаково на всех страницах.
- [ ] Радиусы скругления согласованы по ролям (`rounded-xl` для карточек и информационных блоков, `rounded-lg` для кнопок и полей ввода, `rounded-4xl` для бейджей), без случайного смешения `rounded-md` и `rounded-lg` у одинаковых элементов.
- [ ] Тени используются единообразно (`shadow-xs` / `shadow-sm` для карточек, без случайных глубоких теней).
- [ ] Иконки берутся из единого набора `lucide-react` с согласованными размерами (`size-4` в кнопках и строках метаданных), без смешения с системными эмодзи.
- [ ] Внутренние отступы карточек (`p-5` / `p-6`) и вертикальный ритм секций (`gap-6` / `space-y-5`) выдержаны по единой сетке.

### 3. Полнота состояний интерфейса
Для каждой страницы и интерактивного блока проверены все применимые состояния:
- [ ] **Загрузка**: вместо одиночной текстовой строки показан структурный скелетон или плейсхолдер сопоставимой высоты, чтобы не было скачка макета (CLS).
- [ ] **Пусто**: оформлено аккуратно, объясняет причину и даёт понятный следующий шаг.
- [ ] **Ошибка**: заметна (`variant="destructive"`, `role="alert"`), не ломает макет, даёт способ повторить или исправить.
- [ ] **Успех**: визуально отличается от информационного и ошибочного сообщения, заметна (`role="status"`).
- [ ] **Только чтение (`read-only`)**: визуально отличимо от редактируемого состояния и объясняет причину ограничения.
- [ ] **Заблокировано (`disabled` / `pending`)**: элементы явно приглушены (`disabled:opacity-50`), недоступны для повторного клика, подпись отражает процесс.

### 4. Перегрузка экрана (число одновременных действий и ссылок)
- [ ] В шапке сайта не больше 5–6 видимых навигационных действий на десктопе; вторичные пункты кабинета сгруппированы (например, в меню аккаунта), а не вытянуты в длинную строку.
- [ ] В карточке списка не больше 2–3 видимых действий; остальные сгруппированы (например, в выпадающее меню «Ещё» или на отдельную страницу управления).
- [ ] В фильтрах и тулбарах нет тесноты: контролы не сжимаются в узкие колонки и не перекрывают друг друга.
- [ ] Количество тегов/бейджей в карточке ограничено (например, до 4 + `+N`), текст описания ограничен (`line-clamp-2`).

### 5. Единый чек-лист аудита на каждую страницу
При проверке конкретного маршрута фиксировать по пунктам:
1. **Цель экрана и иерархия**: один `<h1>`, понятный подзаголовок, выделенное главное действие.
2. **Плотность и шум**: число интерактивных элементов в шапке, фильтрах и карточке; нет ли дублей ссылок.
3. **Состояния**: загрузка, пусто, ошибка, успех, `read-only`, `disabled`.
4. **Консистентность примитивов**: единые `Button`, `Badge`, `Input`, `Textarea`, `Select`, `Card`, `Alert`, `AlertDialog`.
5. **Кросс-проверка смежных скиллов**: токены (`design-system`), доступность (`accessibility`), формы (`forms-ux`), брейкпоинты (`responsive`), ясность текстов (`ux-simple-first`).
6. **Формат находки**: `маршрут и файл:строка` → `суть проблемы` → `влияние` → `приоритет P0/P1/P2` → `исправление без изменения логики`.

## Критерии приёмки

- Каждая проверенная страница оценена по всем 5 блокам чек-листа; для каждой находки указаны файл, строки и приоритет.
- Устранены проблемы `P0` (ломают сценарий/вёрстку/доступность) и `P1` (перегрузка, неконсистентность, отсутствующие состояния).
- Все состояния экрана (загрузка, пусто, ошибка, успех, только чтение, заблокировано) проверены в коде и визуально.

## Явные запреты

- Запрещено проводить «аудит на глаз» без проверки реального кода разметки и всех веток состояний (`isPending`, `error`, `empty`, `readOnly`, `disabled`).
- Запрещено смешивать в одной карточке 5+ однотипных кнопок `outline` без группировки и иерархии.
- Запрещено использовать системные эмодзи вместо `lucide-react` в UI-иллюстрациях/пустых состояниях.
- Запрещено менять API, схемы БД или бизнес-правила в рамках UI-аудита и визуальных правок.

## Примеры из проекта

### Хорошие решения
- `src/components/hackathon-card.tsx` (строки 25–138): выверенная иерархия карточки — обложка с инициалом → статус и формат → заголовок → описание (`line-clamp-2`) → метаданные → призовой фонд → максимум 4 тега с `+N` → футер с организатором.
- `src/components/submission-form.tsx` (строки 331–365): на одном экране явно и последовательно разведены состояния `read-only` (иконка `Lock`), информационной подсказки (`Info`), успеха (`CheckCircle2`, `role="status"`) и ошибки (`variant="destructive"`, `role="alert"`).
- `src/components/layout/user-menu.tsx` (строки 20–30): для состояния загрузки сессии предусмотрен плейсхолдер `h-11 rounded-lg bg-muted/60`, предотвращающий скачок шапки.

### Проблемные решения (что нужно улучшать)
- `src/components/hackathon-manage-item.tsx` (строки 146–209): перегрузка действиями — 6 кнопок в ряд («Открыть», «Участники», «Команды», «Работы», «Редактировать», «Удалить»), 5 из них с одинаковым `variant="outline"`, плюс дублирующая ссылка в заголовке.
- `src/components/layout/header-nav.tsx` + `src/components/layout/user-menu.tsx`: для авторизованного пользователя в шапке одновременно выведены логотип, 3 пункта `NAV_ITEMS`, 2 ссылки кабинета («Мои участия», «Мои хакатоны»), имя пользователя и кнопка «Выйти» — 7 интерактивных элементов в одной полосе.
- `src/app/hackathons/page.tsx` (строки 339–345): `Suspense` fallback ограничивается строкой `<p>Загружаем список хакатонов...</p>` вместо скелетона каталога, что вызывает скачок макета при подгрузке.
- `src/app/hackathons/page.tsx` (строка 99): в `NoMatchesState` использован эмодзи `🔍` вместо иконки `Search` из `lucide-react`.
- `src/components/create-hackathon-wizard.tsx` (строка 518) vs `src/components/submission-form.tsx` (строка 434): две `<textarea>` оформлены по-разному (`rounded-lg` без `shadow-xs` vs `rounded-md` с `shadow-xs` и `ring-[3px]`).
