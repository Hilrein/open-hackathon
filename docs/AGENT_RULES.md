# Правила работы для ИИ-агента

- Один таск выполняется за один раз.
- Нельзя добавлять функции вне таска.
- Нельзя удалять существующую рабочую функциональность без явной команды.
- После каждого таска нужно давать отчёт.
- Если задача неясна, нужно выбрать самый простой безопасный вариант и записать это в отчёте.
- Перед завершением таска нужно проверить:
  - установку (`npm install`);
  - dev-сервер (`npm run dev`);
  - сборку (`npm run build`);
  - линтер (`npm run lint`).
- Нельзя подключать внешние сервисы, если это не указано в таске.
- Весь пользовательский интерфейс по умолчанию на русском языке.
- База данных, авторизация и файловое хранилище не добавляются, пока не будет отдельного таска.

## Правила работы с Git

- Один таск — один коммит после успешных проверок.
- Коммит делается только если `npm run build` и `npm run lint` проходят.
- Если таск выполнен частично или проверки падают, коммит не делается, а проблема описывается в отчёте.
- Формат сообщения коммита: `<type>: <краткое описание на русском>`, до 72 символов в первой строке.
- Допустимые типы: `feat`, `fix`, `refactor`, `chore`, `docs`, `style`, `test`.
- В теле коммита при необходимости приводится короткий список ключевых изменений.
- Запрещено коммитить: `.env`, cookie-файлы, файлы с реальными секретами, `node_modules`, `.next`, логи.
- Обязательно коммитить: исходники, конфиги, `drizzle`-миграции и `meta/_journal.json`, `package.json`, `package-lock.json`, `.env.example`, `docs/`.
- `git push` не выполняется без явной команды пользователя.
- Запрещены команды, переписывающие историю или уничтожающие изменения, без явной команды пользователя.
- В отчёте по каждому таску нужно указывать хеш и сообщение коммита.
