# Правила работы с Git

## Основной принцип

Один завершённый таск — один коммит. Коммит создаётся **только после** успешного прохождения `npm run build` и `npm run lint`. Если таск выполнен частично или проверки падают, коммит не делается — проблема фиксируется в отчёте.

## Формат сообщений коммита

Первая строка — до 72 символов:

`<type>: <краткое описание на русском>`

Допустимые типы:
- `feat` — новая функциональность
- `fix` — исправление ошибки
- `refactor` — рефакторинг без изменения поведения
- `chore` — инфраструктура, настройки, зависимости
- `docs` — документация
- `style` — форматирование, стили без изменения логики
- `test` — тесты

При необходимости в теле коммита добавляется короткий список ключевых изменений.

### Примеры

- `feat: страница работ хакатона для организатора`
- `fix: дублированный header в кабинете организатора`
- `refactor: единый расчёт статуса хакатона по датам`
- `chore: подключение Neon и Drizzle`

## Что коммитить и что запрещено

- **Обязательно коммитить:** исходный код (`src/`), конфигурацию, миграции `drizzle/` и `drizzle/meta/_journal.json`, `package.json`, `package-lock.json`, `.env.example`, документацию `docs/`.
- **Запрещено коммитить:** `.env` (и любые `.env.*` с секретами), временные cookie-файлы, файлы с реальными ключами и паролями, `node_modules/`, `.next/`, `*.log`.

## Ограничения

- `git push` не выполняется без явной команды пользователя.
- Команды, переписывающие историю или уничтожающие изменения (`reset --hard`, `filter-branch`, `filter-repo`, `rebase`, `clean -fd`, `checkout -- .`), запрещены без явной команды пользователя.
- В отчёте по каждому таску обязательно указываются хеш и сообщение созданного коммита.
