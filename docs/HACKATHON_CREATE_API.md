# API создания хакатона

## Endpoint

`POST /api/hackathons`

Создаёт новый хакатон в базе данных от имени авторизованного пользователя.

> UI формы создания на странице `/create` будет добавлен в следующем таске.

## Авторизация

Требуется активная сессия пользователя (Better Auth). Без авторизации возвращается статус `401`.

## Входные поля (JSON)

- `title` (строка, обязательно) — от 5 до 120 символов.
- `description` (строка, обязательно) — от 20 до 2000 символов.
- `startDate` (строка, обязательно) — дата начала в валидном формате (не раньше текущего момента более чем на 1 минуту).
- `endDate` (строка, обязательно) — дата окончания в валидном формате (позже `startDate`).
- `location` (строка, обязательно) — место проведения или «Онлайн», от 2 до 120 символов.
- `format` (строка, обязательно) — `online`, `offline` или `hybrid`.
- `organizerName` (строка, необязательно) — до 80 символов. Если не указано, подставляется имя или email пользователя.
- `maxParticipants` (число, необязательно) — целое положительное число до 100 000.
- `prizePool` (строка, необязательно) — до 50 символов.
- `tags` (массив строк, необязательно) — до 8 тегов, каждый от 1 до 30 символов.

## Поля, которые клиент НЕ должен передавать

`id`, `slug`, `status`, `participantsCount`, `organizerId`, `createdAt`, `updatedAt`.

Неизвестные поля отбрасываются при валидации. `slug` генерируется на сервере из `title`, `status` вычисляется по датам, `organizerId` берётся из текущей сессии, `participantsCount` устанавливается в `0`.

## Примеры ответов

### Успех (`201 Created`)

```json
{
  "slug": "testovyy-hakaton"
}
```

### Ошибка авторизации (`401 Unauthorized`)

```json
{
  "error": "Войдите, чтобы создать хакатон."
}
```

### Ошибка валидации (`400 Bad Request`)

```json
{
  "error": "Проверьте поля формы.",
  "fieldErrors": {
    "title": ["Название должно быть от 5 до 120 символов."]
  }
}
```
